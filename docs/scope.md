# ライブラリの責務範囲 (Scope)

本ライブラリが「何を計算し、何を計算しないか」の線引きと、その理由を記します。
公開 API に無い機能を探すとき、まずここを参照してください。

## 原則: 手牌と和了時の局面だけから決まるものを扱う

本ライブラリが扱うのは、**手牌（`Tehai`）と和了時の局面だけで成立が決まる**
役・符・点数です。これを `TehaiYaku` として型で表現しています。

局面とは、和了牌・場風・自風・ツモ/ロン・ドラ表示牌のことです。いずれも
「和了した瞬間の卓の状態」であり、そこに至る打牌の履歴を必要としません。

なお、局面の値はすべて利用側から渡されるものであり、ライブラリはその正しさを
検証しません（誤った `isTsumo` を渡せば門前清自摸和が付きます）。
「ライブラリが検証できるかどうか」は線引きの基準ではありません。基準は
「手牌と局面だけで決まるか」、すなわち役の定義（`TehaiYaku`）に含めるか
どうかの一点です。

## 対象外のもの

以下は本ライブラリでは判定・加算しません。**利用側で加算してください。**

| 分類 | 例 | 対象外の理由 |
| --- | --- | --- |
| 宣言を要する役 | 立直、ダブル立直 | 宣言という行為があったかどうかは手牌に現れない |
| 偶然役 | 嶺上開花、海底摸月、河底撈魚、槍槓、一発 | 和了に至る経緯（どの牌でどう和了したか）を必要とする |
| 裏ドラ | — | 立直を扱わない以上、裏ドラだけを扱うと整合しない（後述） |
| 赤ドラ | — | 牌種 ID (`HaiKindId`) が赤牌を区別しないため（後述） |

### なぜ裏ドラを受け付けないのか

裏ドラは**立直が成立している場合にのみ有効**です。そして上表のとおり、
本ライブラリは立直を役として数えません。

この状態で裏ドラ表示牌だけを受け取ると、「立直の翻は付かないのに裏ドラの翻は
乗る」という、実際の和了には存在しない半端な結果を返すことになります。
裏ドラを扱うなら立直（ダブル立直・一発を含む）を役として数える設計とセットで
なければ整合せず、それは `TehaiYaku` の定義を変える別の設計判断です。

そのため裏ドラは受け口ごと設けず、**立直の翻と裏ドラの翻を必ずセットで
利用側に足させる**設計にしています。

### 利用側で立直・裏ドラを足す手順

翻を後から足しても符と役満単位は変わらないため、元の結果から符と役満単位を
引き継いで `calculateScore` に渡すだけで、点数区分（満貫・数え役満）や
切り上げ満貫の扱いはライブラリの規則どおりに再計算されます。

```ts
import {
  HaiKind,
  calculateScore,
  calculateScoreForTehai,
  countDora,
} from "@pai-forge/riichi-mahjong";

// 1. ライブラリは表ドラまでを計算する
const scored = calculateScoreForTehai(tehai, {
  agariHai,
  isTsumo,
  bakaze,
  jikaze,
  doraMarkers, // 表ドラのみ
  ruleConfig,
});

// 2. 立直の判定は利用側が持っているので、そこで立直と裏ドラを足す
const result = scored.map((base) => {
  if (!isRiichi) return base;

  const riichiHan = isDoubleRiichi ? 2 : 1;
  const uraDoraHan = countDora(tehai, uraDoraMarkers);

  return calculateScore(base.han + riichiHan + uraDoraHan, base.fu, {
    isOya: jikaze === HaiKind.Ton,
    isTsumo,
    ruleConfig, // 元の計算と同じ設定を渡す（切り上げ満貫が点数区分に効く）
    yakumanMultiplier: base.yakumanMultiplier, // 役満役の手は役満単位で支払いが固定される
  });
});
```

`calculateScore` の結果は構造解釈の詳細（`detail`）を持ちません。符の内訳や
待ちの形を表示する側は、元の結果（上記の `base`）の `detail` を参照してください。

> **経緯**: 0.8.x までは `DetectYakuConfig` / `ScoreCalculationConfig` に
> `uraDoraMarkers` フィールドが存在しましたが、値はコンテキストに詰め替えられる
> だけで点数計算からは一度も参照されておらず、渡しても黙って無視される状態
> でした。上記の理由から実装を足すのではなくフィールドを削除しています。

### なぜ赤ドラを扱わないのか

牌種 ID (`HaiKindId`) は 34 種の牌種を表すもので、同じ 5m のうちどれが赤牌かを
区別しません。赤ドラを扱うには牌の表現そのものを変える必要があるため、
現時点では対象外としています（`countDora` 内に TODO があります）。

## 対象範囲の変更について

この線引きを変える場合、**「手牌と局面だけで決まるか」を判断基準にしてください。**
立直や偶然役を入れるなら、`TehaiYaku` の定義を「宣言や経緯に依存する役も含む」
ものへ改め、立直・一発・裏ドラのように互いに前提関係のある要素をまとめて
入れる必要があります。一部だけを入れると、上記の裏ドラのように実際の和了には
存在しない組み合わせを返す口ができます。
